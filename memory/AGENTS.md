# AGENTS.md

> 这是所有 agent 的入口。**只放最小必要信息**，完整规则在 `vault/00-index/RULES.md`——同一规则写两遍就是分叉的开始。

## 这个项目是什么

一个本地的知识库与记忆体。`vault/` 下每个 `.md` 文件是一条记忆，MCP 服务把这些记忆暴露给任何支持 MCP 的 agent。你（agent）既可以读，也可以写。

```
vault/10-knowledge/    客观资料（外部文档、规范、基准数据）
vault/20-memory/       主观上下文（决策 / 事实 / 坑 / 待办 / 笔记）
vault/30-sessions/     会话沉淀
vault/00-index/        RULES.md（规则）与 INDEX.md（自动生成的索引）
```

## 会话启动协议（必须执行，不要跳过）

1. **调 `kb_bootstrap`**，拿到写入规则 + 全部条目的紧凑索引。这一步只建立"有哪些记忆"的地图。
2. **从用户本次问题里提取关键词，调 `kb_search`（k=5）**。不要用"项目""帮助"这类无信息量的词。
3. **只对命中的条目调 `kb_read`**。一次最多读 5 条全文。
4. **没有命中就正常回答**，说明这是新话题，不要硬凑，也不要提"我查了记忆库但没找到"。
5. 如果用户的问题明显属于某个已有决策的范围，先读那条决策再动手，避免推翻已定的方案。

**关键约束：不要一次性读完索引里的所有条目。** 索引是地图，不是内容。全量加载会挤占上下文，且大部分与本轮无关。

## 可用接口

| 方式 | 用法 |
|---|---|
| MCP（推荐） | 工具：`kb_bootstrap` `kb_search` `kb_read` `kb_write` `kb_supersede` `kb_recent` |
| 本地 HTTP | `http://localhost:8787/mcp`（Streamable HTTP，无状态） |
| 云端 | 环境变量 `KB_REMOTE` 指向的地址，鉴权用 `Authorization: Bearer $KB_TOKEN` |
| 命令行 | `node bin/kb.mjs search "关键词"` / `read` / `new` / `supersede` / `lint` |
| 直接读文件 | `vault/**/*.md` 就是真源，任何工具都能读 |

## 什么时候写入

值得记的：

- **决策**：选了 A 不选 B，以及为什么、什么情况下该推翻。
- **事实**：代码里没有、但必须知道的东西（端口、外部系统限制、部署前置条件）。
- **坑**：踩过一次、下次不该再踩的。写清现象 → 原因 → 解法。
- **待办**：有明确下一步的事。

不要记的：代码里能直接读到的、一次性对话细节、未核实的猜测、任何密钥。

## 硬约束

1. **先查后写。** `kb_write` 前必须 `kb_search`，同标题会报错提醒你改用 `kb_supersede`。
2. **事实变更用 `kb_supersede`**，不要新增第二条，也不要手改旧文件。旧条目会保留为 `superseded` 并指向新条目。
3. **永不复制命令到记忆里。** 只写"跑 `package.json` 里的 `build` 脚本"这类**指向**。命令副本必然滞后于真源。
4. **必带 `source`。** 文件路径、URL、PR 号，或"用户口述 @ 日期"。
5. **不存密钥、令牌、手机号、身份证号。** `npm run lint` 会拦截。
6. **记忆的权威低于代码。** 记忆与代码冲突时，去看代码，然后修掉那条记忆。

## 写入格式

正文 50–150 字，第一句就是结论，不要铺垫：

```
结论一句话。

依据：具体数据 / 文件路径 / 复现步骤。
边界：什么情况下这条不适用。
```

## 与其他 agent 协作

- `source` 里注明是哪个 agent 写的，如 `claude-code @ 2026-11-15`。
- 不要改写别人写的条目正文，用 `kb_supersede` 追加你的版本，保留演化链。
- 不确定别人是否记过，先 `kb_search` 再下手。
