## 结论

"接个向量库、把历史对话 embedding 进去"是常见但失败的方案。记忆层真正要解决的是**冲突消解 + 时间有效性 + 作用域**，这三件事向量检索一件都解决不了。

## 依据

用户上周说"只用 Postgres"，这周说"改回 MySQL"。两条都存进去，embedding 相似度几乎相同，检索时一起召回，模型拼出的上下文自相矛盾。

正确做法：写入时归一化成结构化事实（实体 / 属性 / 值 / 来源 / 时间戳 / 置信度），冲突走"覆盖 / 并存待确认 / 反问用户"三选一，失效条目标记而非删除。

## 边界

向量检索对"找相似的历史片段"仍然有价值，适合作为**第二路召回**，但不能替代结构化条目与 supersede 机制。
