2026-11-19 三源验证（Anthropic 多 agent 研究系统官方数据 + 5 篇行业分析 + GitHub 编排仓库）收敛。核心数字：多 agent 耗 15 倍 token（单 agent 4 倍），性能 +90.2%，但性能差异 80% 仅由 token 花费解释——不是更聪明，是烧得多。铁律：①单 agent 优先，直到稳定失败才拆；②拆的判据=中间产物装不下一个上下文窗口，不是想要第二个脑子；③读并行写单线程：搜索/抓取/调研扇出给子 agent，综合决策留主会话；④产物落文件回传指针（brain/library），不走对话搬运；⑤任务书三件套=目标+边界+输出格式；⑥扇出封顶 3-5 个，每个限轮数预算；⑦长调试派子 agent+限预算，报错栈隔离在子会话。定位：子 agent 不省总量，省的是主会话的持续负债。

**补充（2026-11-19）：⑤的输出格式固定为四段式回传——结论 / 踩的坑 / 新事实 / 可复用知识。** 默认子 agent 只回最终结论，坑与事实不会自动回流；必须在任务书里强制「凡遇坑、新事实、可复用做法，无论是否影响任务一律单列；失败时报告卡在哪、为什么」。三层防漏：技术层中间过程留子会话（故意不回流，防主会话膨胀）→ 控制层任务书强制四段 → 兜底层主 agent 收回后做四格扫描（决定/事实/坑/被否方案）列清单问用户记不记。成本：几百 token 一次性，不触发主会话每轮重发的平方级放大；对比漏报后在主流重踩 40 轮调试的代价（每轮上下文十几万 token）完全划算。
