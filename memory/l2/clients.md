# 跨客户端接入与防遗忘（给所有 agent 看的说明书）

> 这份文件回答两个问题：**我一个 agent，怎么接进这个记忆库？**、**我怎样才能不漏掉检索？**
> 规则真源仍是 `D:\collaborative project\brain\AGENTS.md`；这里只写"怎么接、接完怎么验"。
> 改动日期：2026-11-26 ｜ 体检基线：16 项全通过（豆包 2 项为手动）

## 一、三种接入方式，按你的客户端选一种

| 方式 | 适合谁 | 怎么做 | 拿到什么能力 |
|---|---|---|---|
| MCP 服务（模型与工具对接协议） | 支持 MCP 的客户端（WorkBuddy、Codex、Cursor 等） | 配置里加一条 stdio 服务，指向 `memory/server/mcp-server.mjs` | 6 个工具：bootstrap / search / read / write / supersede / recent |
| 命令行 | 任何能执行命令的客户端 | `node memory/bin/kb.mjs …` | 同样的读写能力，靠 shell |
| 只读文件 | 零配置客户端（豆包这类） | 直接读 `memory/vault/**/*.md` | 只能读，写入必须走命令行 |

三条路读的是同一份 Markdown，不存在"各客户端各存一份"。

## 三、防遗忘：三档，按强度从上往下用

### 第一档：短检索（成本最低，强制每天用）

```bash
node memory/bin/kb_hint.mjs "用户刚才的原话"
```

- 输出最多 3 条候选，每条只给标题 + 一句结论，约 150 token（即文本计量单位）。
- 首行固定是 `按记忆：命中 N 条` 或 `按记忆：无命中`——这句是下面闸门的凭据。
- 命中够了，再 `node memory/bin/kb.mjs read <id>` 读 1–2 条全文；不够就换词重跑，别直接放弃。

### 第二档：回复闸（跨客户端都有效，唯一硬约束）

```bash
python memory/bin/reply_gate.py <草稿文件路径>
```

- 两件事一起查：术语有没有「即……」释义、草稿有没有带 `按记忆：…` 那行。
- 退出码非 0 就不许发；与记忆无关的纯计算/纯改写任务可加 `--skip-memory`。
- 为什么有效：它把"我记不记得检索"变成"脚本报不报错"，不靠自觉。

### 第三档：平台钩子（只有部分客户端有）

支持 hook 的客户端能在会话开始自动注入；不支持的（豆包、WorkBuddy 桌面版）只能靠前两档。

## 四、体检（改配置、换电脑、升级客户端后必跑）

```bash
node memory/bin/kb_doctor.mjs
```

16 项检查（原 13 项 + 偏好标准文本 + 副本一致性·WorkBuddy + 副本一致性·豆包手动项）：真源章节齐全、命令行能跑、条目数与索引一致、两家 MCP 配置、六个注入点是否带指针、豆包（手动项）、索引新鲜度。有失败项退出码为 1，按提示修。

## 五、新 agent 接入清单（五步）

1. 选一种接入方式，按第一节做。
2. 在第二节登记表加一行：客户端名、接入方式、注入文件路径、强制手段、已知漏点。
3. 跑 `node memory/bin/kb_doctor.mjs`，确认你这一行是 OK 而不是 FAIL。
4. 会话第一件事跑 `kb_hint` 喂用户原话；回复前跑 `reply_gate`。
5. 要写记忆：先搜（避免同标题重复）→ 得到用户明确同意 → 用 `kb.mjs new` 或 `kb_supersede`，不手改文件。

## 六、边界

- 写入授权永远优先：任何增删改先问用户，不"顺手写"。
- 平台偏好、注入文件都是副本；副本与 `AGENTS.md` 冲突时，以 `AGENTS.md` 为准。
- 偏好的标准句只看 `memory/l2/platform-prefs.md`（核心 6 条）；改了真源，要顺手改它，再去平台同步偏好，最后跑一次体检。
- 豆包与本机路径相关的命令细节只在本机有效，换机器要重新体检（不是重新发明规则）。
