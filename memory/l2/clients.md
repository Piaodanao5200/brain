# 跨客户端接入与防遗忘（给所有 agent 看的说明书）

> 这份文件回答两个问题：**我一个 agent，怎么接进这个记忆库？**、**我怎样才能不漏掉检索？**
> 规则真源仍是 `D:\collaborative project\brain\AGENTS.md`；这里只写"怎么接、接完怎么验"。
> 改动日期：2026-11-26 ｜ 体检基线：20 项（豆包 2 项为手动，偏好同步已自动比对）

## 一、三种接入方式，按你的客户端选一种

| 方式 | 适合谁 | 怎么做 | 拿到什么能力 |
|---|---|---|---|
| MCP 服务（模型与工具对接协议） | 支持 MCP 的客户端（WorkBuddy、Codex、Cursor 等） | 配置里加一条 stdio 服务（即以标准输入输出管道通信的本地服务），指向 `memory/server/mcp-server.mjs` | 7 个工具：bootstrap / search / read / write / supersede / recent / daily（即按天汇总） |
| 命令行 | 任何能执行命令的客户端 | `node memory/bin/kb.mjs …` | 同样的读写能力，靠 shell |
| 只读文件 | 零配置客户端（豆包这类） | 直接读 `memory/vault/**/*.md` | 只能读，写入必须走命令行 |

三条路读的是同一份 Markdown，不存在"各客户端各存一份"。

## 三、防遗忘：三档，按强度从上往下用

### 第一档：短检索（成本最低，约定每天用）

```bash
node memory/bin/kb_hint.mjs "用户刚才的原话"
```

- 输出最多 3 条候选，每条只给标题 + 一句结论，约 150 token（即文本计量单位）。
- 首行固定是 `按记忆：命中 N 条` 或 `按记忆：无命中`——这句是下面闸门的凭据。
- 它是约定，不是硬要求；但它其实是间接硬要求：闸带原话运行时会把这条命令自己再跑一遍，草稿里那行要与实测逐字一致，没跑就拿不到真凭据。
- 命中够了，再读全文：`node memory/bin/kb.mjs read <完整编号>`。读取只认三种键——完整编号、完整相对路径、完整标题；4 位短号与标题片段都会报错。报错时加 `--json`（即输出结构化数据）重跑短检索，从结果里取编号，或 `node memory/bin/kb.mjs search "词"` 查。

### 第二档：回复闸（跨客户端都有效，唯一硬约束）

```bash
python memory/bin/reply_gate.py <草稿文件路径> --query "用户刚才的原话"
```

- 两件事一起查：术语有没有「即……」释义、草稿有没有带 `按记忆：…` 那行。给了 `--query` 之后，它还会现场重跑 kb_hint，与草稿那行逐字比对——编造、改写都过不去。
- 退出码非 0 就不许发；与记忆无关的纯计算/纯改写任务可加 `--skip-memory`。
- 为什么有效：它把"我记不记得检索"变成"脚本报不报错"，不靠自觉。

### 第三档：平台钩子（只有部分客户端有）

支持 hook 的客户端能在会话开始自动注入；不支持的（豆包、WorkBuddy 桌面版）只能靠前两档。

## 四、体检（改配置、换电脑、升级客户端后必跑）

```bash
node memory/bin/kb_doctor.mjs
```

20 项检查：真源章节齐全、命令行能跑、条目数与索引一致、两家 MCP 配置、六个注入点是否带指针、副本有没有抄命令、偏好标准文本、副本一致性（WorkBuddy 自动查 / 豆包手动）、偏好同步·豆包（拿快照比对核心六条）、索引新鲜度、作废条目是否堆积（超 20 条提醒）、注入副本有没有写会变的数字（条数、版本号）。有失败项退出码为 1，按提示修。

作废条目满了别手动删，跑这个：

```bash
node memory/bin/kb_archive.mjs          # 只列满 90 天的候选
node memory/bin/kb_archive.mjs --apply  # 真移进 90-archive
```

## 五、新 agent 接入清单（五步）

1. 选一种接入方式，按第一节做。
2. 在第二节登记表加一行：客户端名、接入方式、注入文件路径、强制手段、已知漏点。
3. 跑 `node memory/bin/kb_doctor.mjs`，确认你这一行是 OK 而不是 FAIL。
4. 会话第一件事跑 `kb_hint` 喂用户原话；回复前跑 `reply_gate`。
5. 要写记忆：先搜（避免同标题重复）→ 得到用户明确同意 → 用 `kb.mjs new` 或 `kb_supersede`，不手改文件。

## 六、命令只住真源：其他 agent 怎么跟着变

核心办法就一句：**副本里不抄命令，只写"读 brain/AGENTS.md 第 8/9 条"**。命令只留在真源，改真源 = 全体客户端下一轮自动生效，不需要挨个改文件。

为什么这么定：

- 抄一段命令进副本，真源一改（比如闸加了 `--query`），副本立刻变成旧的，而且没有任何机制会提醒。
- 只放指针，最坏情况是"没读到"，不会出现"读到的是旧写法"。

每个客户端拿到最新规则的方式：

| 客户端 | 怎么拿到 | 会不会自动跟 | 出问题会怎么暴露 |
|---|---|---|---|
| WorkBuddy | 每会话注入 `MEMORY.md`，其中「启动必读」指向真源 | 会（副本只有指针，无命令） | 用旧写法跑闸 → 闸判失败，当场报错 |
| Codex | 自动读 `~/.codex/AGENTS.md` 指针 + MCP | 会 | 同上 |
| CodeBuddy | 自动读 `~/.codebuddy/AGENTS.md` 与 `CLAUDE.md` | 会 | 同上 |
| 通用 agents | 自动读 `~/.agents/AGENTS.md` | 会 | 同上 |
| DSH | 开会话注入 `dsh-home/AGENTS.md` | 会 | 同上 |
| 豆包 | 平台偏好指名去读真源 | 会（前提是偏好那句没被改坏） | 同上；偏好本身旧了由体检人工比对 |

三道保险，按强度排：

1. **闸会判失败**：命令写旧了（比如闸少了 `--query`），脚本直接退出码 1，不许发。这是唯一"不靠自觉"的一道。
2. **体检会抓抄命令**：第「副本无命令漂移」项会扫 6 个注入点，发现里面抄了闸或检索脚本的命令就报提醒，提示删成指针。
3. **说明书登记表**：新增客户端必须登记一行并跑体检，否则没人知道你接进来过。

## 七、边界

- 写入授权永远优先：任何增删改先问用户，不"顺手写"。
- 平台偏好、注入文件都是副本；副本与 `AGENTS.md` 冲突时，以 `AGENTS.md` 为准。
- 偏好的标准句只看 `memory/l2/platform-prefs.md`（核心 6 条）；改了真源，要顺手改它，再去平台同步偏好，最后跑一次体检。
- 豆包与本机路径相关的命令细节只在本机有效，换机器要重新体检（不是重新发明规则）。
- 被取代（superseded，即被新条目顶替、标记作废）的旧条目不会自动删除。规则是作废满 90 天移进 `90-archive`：先跑 `node memory/bin/kb_archive.mjs` 看候选，确认后加 `--apply` 才真移，不物理删除、随时能从归档找回来。
- 豆包平台偏好在服务端，本地读不到文件。自动比对的办法是快照：把平台列表照抄进 `memory/l2/doubao-prefs-snapshot.md`，体检第 20 项拿它比对 `platform-prefs.md` 的核心六条，缺哪条就报。
- 注入文件是会话启动时的快照（即那一刻定格的副本），真源改完后、平台重新加载前仍可能读到旧版；有疑问以磁盘上的真源为准。体检第 19 项会扫注入文件里有没有写条数、版本号这类会变的数字，写了就提醒。
